THE ONE THING THAT BREAKS IT

Android will not install the app, and the background worker will not run, unless the page is served over HTTPS from a real domain. Opening the file directly, or from a file:// path, or the single-file offline copy, silently disables both. If the Install option never appears in Chrome’s menu, that is almost always why.

Where the numbers come from

{{ s.name }} {{ s.role }} {{ s.checked }}

A browser page cannot scrape those three sites directly — they block cross-origin requests and publish no open API. So the app ships with a verified snapshot, cross-checked across all three, and there are two ways to keep it current.

A · EDIT THE SOURCE

The snapshot below is hand-checked against all three sites. To revise it, edit the MRDN_EVENTS array inside app.dc.html and re-upload the file to your repository — each entry carries its own actual, consensus, previous and per-site impact rating. Your notes, watchlist, timezone and alert settings live on this device and are never affected by a data update.

B · LIVE FEED — RECOMMENDED

The only way to keep the calendar current without touching the source. Point the app at a JSON endpoint returning the same shape — Trading Economics, FMP, Finnhub or your own scraper — and it pulls on every load and merges over the snapshot, so actuals, revisions and schedule changes arrive on their own. Every filter, alert and report keeps working.
